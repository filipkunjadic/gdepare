1. Export makes a function available

    
In useFetch.js:
export function useFetch(url) {
    // Create state and a load function.
    return { data, loading, error, load };
}
In Page.vue:
import { useFetch } from '../composables/useFetch.js';

const result = useFetch('/data');

    
export exposes the function to other files. import gives the page access to that function. Neither starts this request. Calling useFetch('/data') creates the state and returns it.

    
The returned load function remembers the URL '/data' and the refs created by that particular call.

  


  

    
2. Return hands the state back to the page

    
This shorthand:
const { data, loading, error, load } = useFetch('/data');
Means the same thing as:
const result = useFetch('/data');
const data = result.data;
const loading = result.loading;
const error = result.error;
const load = result.load;

    
The page receives the same ref objects that the composable created. They are not copies. When load() changes data.value, the page sees the new value.

    
A ref is a box Vue watches. JavaScript reads or writes its contents with .value. In a template, Vue unwraps these refs automatically.

    
// JavaScript
loading.value = false;

// Vue template
<p v-if="loading">Loading…</p>

  


  

    
3. Components communicate in three ways here

    
MechanismDirectionMeaning

      
Props
:loading="loading"		Page → Loader“Here is my current loading value.” The left name is the child’s prop; the right expression reads the page’s variable.

      
Event
@retry="load"		Loader → Page“The retry button was clicked.” The page listens and runs its load function.

<slot />		Page supplies contentThe page supplies its list HTML. The loader decides when to display it. That HTML still reads the page’s data.

    

    
Page’s loading ref changes→Loader’s prop updates→Vue updates the visible branch

    
The loader never fetches cards and never needs to know what a card is. It can wrap a customer list, a chart, or a profile using exactly the same rules.

  


  

    
4. The complete three files

    
These are learning examples, not changes to your application. The server is expected to return an object with a cards array.

    
composables/useFetch.js — the reusable logic
import { ref } from 'vue';

export function useFetch(url) {
    const data = ref(null);
    const loading = ref(true);
    const error = ref('');

    async function load() {
        loading.value = true;
        error.value = '';

        try {
            const response = await fetch(url, {
                headers: { Accept: 'application/json' },
            });

            if (!response.ok) {
                throw new Error('Request failed');
            }

            data.value = await response.json();
        } catch {
            error.value = 'Could not load data.';
        } finally {
            loading.value = false;
        }
    }

    return { data, loading, error, load };
}
async allows await: this function waits for the response without freezing the browser. catch handles failure. finally finishes the loading state in either case.

    
components/LoadingState.vue — the reusable display
<script setup>
defineProps({
    loading: Boolean,
    error: String,
});

defineEmits(['retry']);
</script>

<template>
    <div :aria-busy="loading">
        <p v-if="loading" role="status">Loading…</p>

        <div v-else-if="error" role="alert">
            <p>{{ error }}</p>
            <button type="button" @click="$emit('retry')">
                Try again
            </button>
        </div>

        <slot v-else />
    </div>
</template>
defineProps declares inputs. defineEmits declares events. Vue’s compiler understands these inside <script setup>. The component does not export these as ordinary JavaScript functions.

    
pages/Page.vue — the coordinator
<script setup>
import { onMounted } from 'vue';
import Layout from '../components/Layout.vue';
import LoadingState from '../components/LoadingState.vue';
import { useFetch } from '../composables/useFetch.js';

const { data, loading, error, load } = useFetch('/data');

onMounted(load);
</script>

<template>
    <Layout>
        <h1>Cards</h1>

        <LoadingState
            :loading="loading"
            :error="error"
            @retry="load"
        >
            <template v-if="data">
                <p v-if="data.cards.length === 0">No cards found.</p>
                <ul v-else>
                    <li v-for="card in data.cards" :key="card">
                        {{ card }}
                    </li>
                </ul>
            </template>
        </LoadingState>
    </Layout>
</template>
Importing a .vue file gives you a component. With <script setup>, imported components can be used directly in the template. onMounted(load) asks Vue to run the request after mounting this page.

  


  

    
5. Does loading one page affect another?

    
Cards page
useFetch('/data')
Creates its own data, loading, error, and load function.
Customers page
useFetch('/customers')
Creates a different set of data, loading, error, and load function.

    
These calls reuse the same logic, but do not share state. A store is useful when you deliberately want multiple components to share the same data.

    
A composable does not automatically cache requests or persist data after the page is destroyed. This example also leaves request cancellation and overlapping-request handling for a later lesson.
